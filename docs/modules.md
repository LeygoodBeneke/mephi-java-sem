# Документация по модулям

Точка входа и сборка — в конце. Про слои и поток данных см. раздел «Архитектура» в
[README](../README.md#архитектура).

## core.model — предметные сущности

| Класс | Ответственность |
|---|---|
| `ShortCode` | короткий код: валидация base62 и длины 4..12, регистр значим; `fromLink()` вынимает код из полной ссылки, срезая хвост пути и query |
| `ShortLink` | ссылка: код, владелец, исходный URL, `createdAt`, `expiresAt`, лимит и счётчик переходов. Счётчик и лимит изменяемы, поэтому методы над ними `synchronized`; `registerRedirect` проверяет лимит и инкрементирует в одном мониторе; `claimLimitNotice`/`claimTtlNotice` — «первый победитель» на `AtomicBoolean`, чтобы уведомление не дублировалось |
| `UserId` | обёртка над `UUID`: `random()` для выдачи, `parse()` для ручного ввода с понятной ошибкой |
| `LinkStatus`, `UnavailabilityReason` | состояние ссылки (вычисляется, не хранится) и причина отказа с готовым предложением создать новую ссылку |
| `Notification` | событие для владельца: вид (`LIMIT_EXHAUSTED`/`TTL_EXPIRED`), адресат, код, текст, момент |
| `Durations` | человекочитаемая длительность для консоли и текстов уведомлений |

## core.repository, core.port — контракты

```java
interface LinkRepository { save / findByCode / findByOwner / findAll / delete(code, owner) / count }
interface LinkOpener     { OpenResult open(String targetUrl) }
```

`delete` принимает владельца: контроль доступа нельзя потерять, забыв проверку в новом месте.
Порты нужны, чтобы `core` не зависел от хранилища и от `java.awt`, а тесты получали подставные
реализации.

## core.service — правила

- **`LinkService`** — сокращение (`create`: валидация URL → границы лимита → выдача свободного кода
  до 10 попыток → `expiresAt = now + link.ttl`), переход (`redirect` → `RedirectResult` с итогом,
  остатком и ответом браузер-подсистемы; исключение не бросается, недоступная ссылка — штатный
  исход), доступ к ссылке только владельцу (`ownedLink`), изменение лимита (`updateLimit`: диапазон
  из конфигурации и больше уже засчитанных), удаление (`delete`).
- **`ExpirationService`** — `purgeExpired()` удаляет устаревшие на текущий момент ссылки и
  уведомляет владельцев; возвращает список удалённых. Один код для фона, команды `purge` и тестов.
- **`NotificationCenter`** — очередь до 50 сообщений на пользователя, `pending`/`drain`; в
  «глухом» режиме (`notifications.enabled=false`) ничего не копит. Каждое сообщение дублируется в
  лог-канал `notifications`.
- **`UserSession`** — `identify()` выдаёт UUID при первом обращении и больше его не меняет;
  `becomeNewUser()`/`use(uuid)` — переключение для проверки мультирежима и прав; `knownUsers()` —
  все замеченные UUID.
- **`LinkNotifications`** — тексты уведомлений в одном месте: событие возникает из перехода, из
  обращения к устаревшей ссылке и из автоочистки.

## core.config — конфигурация

`AppConfig` (record, 11 параметров) проверяет согласованность в компактном конструкторе — поля
присваиваются после тела конструктора, поэтому проверяются параметры. Ошибка всегда называет
проблемный ключ. `ConfigLoader` читает properties (UTF-8), понимает длительности `45s/30m/24h/7d` и
ISO-8601, переопределяет значения JVM-свойствами, определяет путь к файлу
(`--config` → `-Dshortlink.config` → дефолт) и возвращает defaults, если файла нет.

## core.generation, core.validation

`ShortCodeGenerator` — интерфейс для тестируемости (в тестах детерминированные `SEQ001…`),
`Base62CodeGenerator` — `SecureRandom` + алфавит base62, длина из конфигурации.
`UrlValidator` — только абсолютные http/https с хостом; rejects `userinfo`, пробелы (подсказка про
кавычки), слишком длинные адреса и ссылки самого сервиса (цикл редиректа); возвращает URL без
обрамляющих пробелов.

## core.exception

`DomainException` — checked-базовое, сообщение пригодно для показа в консоли; `NotOwnerException`
выделен типом, потому что разграничение доступа — отдельное требование (6 баллов рубрики);
`ConfigException` — unchecked: ошибка конфигурации возникает до старта цикла обработки ошибок.

## infrastructure

- `memory.InMemoryLinkRepository` — `ConcurrentHashMap<ShortCode, ShortLink>`; `save` =
  `putIfAbsent`, `delete` сверяет владельца и использует `remove(key, value)`; списки отсортированы
  по `createdAt`, затем по коду.
- `browser.DesktopLinkOpener` — `Desktop.browse(new URI(url))` с проверками поддержки и обработкой
  `IOException`/`URISyntaxException`/сбоев: вместо падения — адрес для ручного открытия.
- `browser.ConsoleLinkOpener` — печать адреса (`browser.open=false`, headless, CI).
- `scheduler.ExpirationScheduler` — `AutoCloseable` вокруг одного демон-потока
  (`scheduleWithFixedDelay`, имя `link-cleanup`); период `<= 0` отклоняется; исключение итерации
  логируется и не останавливает очистку; `close()` — `shutdownNow` + ожидание 2 с.

## cli

- `ConsoleApplication` — баннер, цикл `чтение → interpret → parse → dispatch → доставка
  уведомлений`; ошибки пользователя печатаются как текст с подсказкой и не прерывают сессию,
  внутренние — в лог; `runOnce` возвращает 0/1/2.
- `CommandParser`/`CommandLine` — токены с учётом одинарных и двойных кавычек, глагол в нижний
  регистр, `--опция=значение` и `--флаг`; `requireArg`/`optionAsInt` дают внятные сообщения.
- `Command`/`CommandRegistry` — команда описывает имя, алиасы, `usage`, `summary`, `details` и
  выполняет их; `execute` возвращает `false` только для `exit`; `--help` у любой команды печатает
  справку вместо выполнения.
- `CommandContext` (record) — сервисы, конфигурация, часы, реестр, источник настроек и `PrintWriter`;
  `requireUser()` объясняет, что UUID появится при первом `new`.
- `OutputFormatter` — таблица ссылок, карточка ссылки, итог перехода (с причиной и предложением
  создать новую) и блок уведомлений.
- `commands.LinkCommands` / `commands.SessionCommands` — 11 команд консоли (см. таблицу в README).

## Точка входа и сборка

`ShortLinkApplication` разбирает аргументы процесса (флаги до команды, опции команды — после глагола),
загружает конфигурацию, печатает `--help` и выбирает режим: интерактив или однократное выполнение.
`app.AppContainer` — единственное место, где известно, какие реализации стоят за портами: собирает
хранилище, генератор, валидатор, уведомления, браузер (с учётом `browser.open` и headless), сервисы,
реестр команд, `CommandContext` и фоновый планировщик; реализует `AutoCloseable`, чтобы остановить
поток очистки.

## Тестовые двойники (src/test/…/support)

`MutableClock` — перематывает время; `RecordingLinkOpener` — помнит открытые адреса и умеет падать;
`ScriptedCodeGenerator` — детерминированные коды и воспроизведение коллизий; `Fixtures` — сборка
`Harness` (сервисы) и `Cli` (сервисы + реестр команд + перехваченный вывод) на тех же классах, что и
в бою.
