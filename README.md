# Сервис коротких ссылок (консольный)

Учебный проект курса «Java-разработчик» (МЭИ) по ТЗ PROMO IT: сокращение длинных URL, лимит
переходов, автоматически удаляемые по сроку ссылки, идентификация пользователя по UUID.

Java 17 · Maven · зависимостей в основном коде нет · 90 тестов (138 прогонов) · покрытие строк 89,3%

## Быстрый старт

Требования: JDK 17+, Maven 3.8+. Ставить что-то отдельно не нужно: основной код зависит только на
JDK, а JUnit 5 и плагины Maven подтягивает сам из Maven Central (для офлайна —
`mvn dependency:go-offline`).

```bash
mvn verify                        # линт + тесты + отчёт покрытия
java -jar target/short-link-service-1.0.0.jar
./run.sh --no-browser             # то же самое, но без открытия браузера
```

Как выглядит сессия:

```
shortlink> new https://www.baeldung.com/java-9-http-client 3
  Вы зарегистрированы по UUID: 6f2c1e0a-83c5-4d7b-9d0e-a1b2c3d4e5f6 — сохраните его.
  Готово: https://clck.ru/8pyuw3
  Исходный URL:    https://www.baeldung.com/java-9-http-client
  Лимит переходов: 3
  Автоудаление:    2026-11-10T15:57:14Z (через 1 д)
  Переход: open 8pyuw3 — или вставьте короткую ссылку

shortlink> open 8pyuw3
  Переход выполнен: https://clck.ru/8pyuw3 → https://www.baeldung.com/java-9-http-client
  Браузер открыт
  Засчитано переходов: 1 из 3, осталось 2
```

## Команды

| Команда | Что делает |
|---|---|
| `new <url> [лимит]` | сократить URL; опция `--limit=N` то же самое |
| `open <код\|ссылка>` | засчитать переход и открыть браузер (`go`) |
| `list` | таблица моих ссылок: переходы, лимит, статус, время до автоудаления |
| `show <код>` | подробности моей ссылки, включая время последнего перехода |
| `edit <код> --limit=N` | изменить лимит; разблокирует ссылку с исчерпанным лимитом |
| `delete <код>` | удалить мою ссылку (`rm`) |
| `whoami` | мой UUID и число ссылок |
| `as new \| <uuid>` | переключить пользователя (`switch`) — проверка прав и мультирежима |
| `purge` | немедленно удалить устаревшие ссылки |
| `help [команда]` | список команд и подробности (`?`; у любой команды есть `--help`) |
| `exit` | выйти (`quit`, `q`) |

Опции процесса ставятся **до** команды: `--config <файл>`, `--no-browser`, `-h|--help`.
Можно не заходить в интерактив: `java -jar … --no-browser new https://example.com 5`. Это удобно
для справки и дымовой проверки: хранилище in-memory, поэтому созданная в однократном режиме ссылка
исчезает вместе с процессом — для работы с ссылками нужен интерактив.

Код возврата: `0` успех, `1` команда не выполнена, `2` ошибка опций запуска или конфигурации, `3`
сбой. В интерактивном режиме код относится к сессии: штатный `exit` или конец ввода — `0`, ошибки
отдельных команд его не меняют.

## Инструкция пользователя

1. Сократите ссылку: `new <url> [лимит]`. Сервис выдаст короткую ссылку и ваш UUID — сохраните его,
   авторизации нет и без UUID вы не вернётесь к своим ссылкам.
2. Переход: `open <код>` или вставка полной короткой ссылки. Переход засчитывается, адрес
   открывается в браузере.
3. Свои ссылки: `list`, детали — `show <код>`, кто я — `whoami`.
4. Управление: `edit <код> --limit=N` (лимит из диапазона конфигурации и больше уже засчитанных),
   `delete <код>`. Срок жизни не меняется — его задаёт система.
5. Если лимит выбран, уведомление с предложением создать новую ссылку выводится сразу после
   исчерпывающего перехода. Если срок истёк и ссылку удалил фоновый планировщик — при следующем
   обращении к консоли; при `open`/`purge` — сразу.
6. Проверить изоляцию пользователей: `as new`, затем `show`/`edit`/`delete` первой ссылки — отказ.

Переход по чужой ссылке разрешён: сам переход публичен и показывает исходный адрес; приватны
карточка ссылки (`show`), список (`list`) и управление (`edit`/`delete`).

## Конфигурация

Все ключевые параметры (TTL, лимиты, длина кода и т. д.) читаются из `config/application.properties`;
в коде остались значения по умолчанию, совпадающие с файлом, и проверки допустимых диапазонов
(например, TTL не больше 365 дней).

| Ключ | По умолчанию | Значение |
|---|---|---|
| `link.ttl` | `24h` | срок жизни ссылки; формат `45s`/`30m`/`24h`/`7d` или ISO-8601 `PT24H` |
| `link.redirect-limit.default` | `50` | лимит переходов, если свой не указан |
| `link.redirect-limit.min` / `.max` | `1` / `1000` | границы запроса лимита |
| `link.code-length` | `6` | длина кода base62 (4..12) |
| `service.base-url` | `https://clck.ru/` | префикс короткой ссылки |
| `link.url.max-length` | `2048` | предельная длина исходного URL |
| `cleanup.enabled` / `cleanup.interval` | `true` / `1m` | фоновое автоудаление и его период |
| `notifications.enabled` | `true` | доставлять ли уведомления |
| `browser.open` | `true` | false — печатать адрес вместо открытия браузера |

Приоритет: JVM-свойство (`-Dlink.ttl=10m`) → файл → значения по умолчанию. Путь к файлу:
`--config <файл>` → `-Dshortlink.config` → `config/application.properties`; если файла нет, сервис
стартует на defaults и пишет предупреждение. Битое значение — ошибка с именем ключа и код возврата 2.

Профиль `config/application.fast-ttl.properties` (`link.ttl=1m`, `cleanup.interval=5s`) нужен, чтобы
наблюдать автоудаление без суток ожидания.

## Как это работает

- **Код ссылки** — случайный base62 (`SecureRandom`), а не хеш от URL: иначе один и тот же ресурс
  давал бы одинаковые коды разным пользователям. Уникальность гарантирует `putIfAbsent` в
  хранилище, при коллизии код перевыпускается (до 10 попыток).
- **Лимит** — проверка «не выбран» и инкремент счётчика в одном `synchronized`-методе, поэтому два
  одновременных перехода не обходят блокировку.
- **Статус не хранится**, а вычисляется из счётчика и `expiresAt`: повышение лимита само открывает
  ссылку, расхождение данных невозможно.
- **Автоудаление** — `ExpirationService.purgeExpired()` вызывается из фонового демон-потока
  (`cleanup.interval`), из команды `purge` и лениво при обращении к устаревшей ссылке.
- **UUID и права** — `UserSession.identify()` выдаёт UUID при первом `new`; `show`/`edit`/`delete`
  проходят через `LinkService.ownedLink`, `delete` в хранилище тоже требует владельца.
- **Уведомления** — событие `Notification` в очередь владельца + запись в лог. Уведомление о лимите
  выводится сразу после исчерпывающего перехода, об истечении TTL — когда владелец снова обратится
  к консоли (при `open`/`purge` — сразу). Идемпотентность через `claimLimitNotice()`/`claimTtlNotice()`:
  одно событие — одно сообщение, даже если его заметили переход и очистка одновременно.
- **Переход** — ровно то, что требует ТЗ: `Desktop.getDesktop().browse(new URI(url))`; в headless
  или при `browser.open=false` адрес печатается, сбой браузера не роняет сессию.

## Архитектура

Зависимость направлена вниз: `cli` → `core`, а реализации портов подключает `app.AppContainer`.

```
ru.mephi.shortlink
├── ShortLinkApplication      аргументы процесса, конфигурация, запуск консоли
├── app.AppContainer          DI: какие реализации стоят за портами
├── core                      правила домена, без I/O
│   ├── model                 ShortCode, ShortLink, UserId, Notification, LinkStatus…
│   ├── repository            LinkRepository — контракт хранилища
│   ├── port                  LinkOpener — контракт открытия браузера
│   ├── service               LinkService, ExpirationService, NotificationCenter, UserSession
│   ├── generation            Base62CodeGenerator
│   ├── validation            UrlValidator
│   ├── config                AppConfig, ConfigLoader
│   └── exception             DomainException, NotOwnerException, ConfigException
├── infrastructure            InMemoryLinkRepository, Desktop/ConsoleLinkOpener, ExpirationScheduler
└── cli                       ConsoleApplication, CommandParser, CommandRegistry, команды, вывод
```

Почему так: `core` не знает ни про консоль, ни про `java.awt` — сервисы тестируются без терминала и
без реального браузера, а замена хранилища (например на JDBC) не трогала бы бизнес-логику.
Подробности по каждому модулю — [docs/modules.md](docs/modules.md).

```bash
mvn test     # 90 тестов (138 прогонов)
mvn verify   # + checkstyle, spotless, отчёт покрытия target/site/jacoco/index.html
```

Покрытие: 89,3% строк, 80,9% ветвей. Юниты — модель, конфигурация, валидатор, генератор, сервисы,
хранилище, парсер; интеграция — `SpecificationScenariosTest` (четыре проверки этапа 3 ТЗ: уникальные

`CliTest` (команды идут тем же кодом, что при интерактиве). Браузер, время и коды подставлены
(`src/test/java/ru/mephi/shortlink/support`), поэтому тесты не ждут суток и не открывают вкладки.

Проверка руками за минуту:

```bash
mvn -q package
java -jar target/short-link-service-1.0.0.jar --no-browser --config config/application.fast-ttl.properties
```

В консоли: `new https://example.com 2`, затем `open <код>` дважды — третий переход блокируется и
приходит уведомление о лимите; через ~70 с планировщик удаляет ссылку, `list` пустой и приходит
уведомление о сроке жизни. Тот же TTL можно поменять без файла: `-Dlink.ttl=10m`.

## Ограничения

- Хранилище — память процесса: после `exit` ссылки и UUID теряются (интерфейс `LinkRepository`
  позволяет добавить персистентность, не меняя сервисы).
- Один процесс: уведомление о TTL, удалённом фоновым планировщиком, доставляется при следующем
  обращении к этой же консоли; уведомление о лимите выводится сразу.
- HTTP-API нет: `https://clck.ru/<код>` — внутренний идентификатор сервиса, вне консоли он не
  резолвится; переход выполняет команда `open`.
